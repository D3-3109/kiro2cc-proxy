# 变更提案：remove-redundant-kam-import

## 背景
“KAM 批量导入”已经兼容单账号 KAM JSON，独立的“KAM 导入”入口及弹窗与其功能重复，增加界面认知成本和维护成本。

## 目标范围
**在范围内：**
- 删除账号管理操作栏中的“KAM 导入”按钮。
- 删除独立 KAM 导入弹窗及其打开状态、属性传递和组件引用。
- 删除 `kam-import-dialog.tsx` 组件文件。
- 删除仅由独立 KAM 导入功能使用的中英文翻译键。
- 保留“KAM 批量导入”按钮、弹窗、KAM 下载入口及单账号导入兼容能力。

**不在范围内：**
- 不修改 KAM 批量导入的数据解析与账号创建逻辑。
- 不修改后端 Admin API。
- 不修改普通“添加账号”功能。
- 不修改批量验活、账号删除或账号状态管理功能。

## 技术方案
沿现有 Dashboard 组件属性链反向删除独立 KAM 导入入口：从操作栏移除按钮，从 `CredentialList` 和 `Dashboard` 移除回调与弹窗状态，从 `DashboardDialogs` 移除弹窗挂载，最后删除组件文件和失效翻译键。共享翻译键和 `KAM_RELEASES_URL` 继续由批量导入弹窗使用。

## 预期影响
账号管理操作栏只保留“KAM 批量导入”入口。用户仍可通过该入口导入单个或多个 KAM 账号，现有后端行为不变。

## 风险
- 误删批量导入共享翻译键可能导致界面显示键名；通过引用扫描和生产构建验证。
- 遗留组件属性或导入可能导致 TypeScript 构建失败；通过 `pnpm --dir admin-ui build` 验证。
- 工作区存在其他未提交改动；实施时仅修改本提案范围内代码，不覆盖既有改动。

## 经确认的主动补充
- 保留 KAM 下载入口。
- 不修改后端 Admin API、普通“添加账号”、批量验活、账号删除或账号状态管理功能。
- 保留引用扫描、JSON 解析和 Admin UI 生产构建验证要求。

以上内容超出原始需求的直接表述，已由用户确认保留。
